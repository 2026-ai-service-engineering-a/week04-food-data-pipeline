# week04-food-data-pipeline — 가공식품 영양 탐색기 🍜

식약처 가공식품 DB **306,307건**을 정제해 검색·RAG 서비스로 만드는 4주차
라이브 시연 저장소입니다.

3주차의 `foods.json`은 누가 미리 치워둔 결과였습니다. 이번 주는 치우기 전의
원본을 직접 만납니다. 그리고 31만 건이라는 몸집 때문에 생기는 문제 — 컨텍스트에
다 안 들어가고, 전량 LLM은 비싸다 — 를 **검색**으로 풉니다.

```
원본 엑셀 187MB ──┬── 1회전 정제 + 섭취참고량 파싱 ──┬── 2회전 PostgreSQL ──┐
  (레포 밖)        │   (정제 데이터셋 = 이번 주 산출물) └── 3회전 Chroma ──────┤
                   │                                                          │
                   └── data/sample/raw_sample.csv           FastAPI ───────────┴── Streamlit
                       (1,000건, 커밋됨)            검색 · 의미 검색 · /ask
```

비용 사다리가 전체를 관통합니다. **SQL(공짜) → 임베딩(싸다) → LLM(비싸다).**
싼 층에서 풀리는 문제를 비싼 층으로 가져가지 않습니다.

## 시작하기

기본 브랜치 `main`은 완성본입니다. 그냥 클론하면 정답을 받으니, 시작점은
**v0.1 태그**에서 작업 브랜치를 잡습니다.

```bash
git clone https://github.com/2026-ai-service-engineering-a/week04-food-data-pipeline.git
cd week04-food-data-pipeline
git switch -c week04 v0.1

cp .env.example .env
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

- UI: http://localhost:8501 · API 문서(Swagger): http://localhost:8000/docs
- v0.1은 **키 없이도 뜹니다** — UI에 "데이터가 아직 없습니다" 빈 상태 화면이 나옵니다
- v0.1이 v1.0이 되는 순간은 코드가 아니라 **이 화면이 채워지는 순간**입니다

회전마다 릴리즈 태그를 자릅니다. 태그 하나가 "이 지점의 코드 + 이 지점의 데이터"를
가리킵니다.

| 회전 | 브랜치 | 릴리즈 | 함께 배포되는 산출물 |
| --- | --- | --- | --- |
| 1회전 정제 + 섭취참고량 파싱 | `feature/clean` | v0.2 | `foods_parsed.parquet` · `clean_report.txt` · `parse_report.txt` · `rejected.csv` |
| 2회전 PostgreSQL 검색 서비스 | `feature/pg-service` | v0.3 | `foods.dump` (pg_dump) |
| 3회전 RAG 검색 | `feature/rag-search` | v1.0 | `chroma_foods.tar.gz` (Google Drive) · `embed_report.txt` |

## 데이터

- **출처**: [식품안전나라 K-FIND 식품영양성분 DB 내려받기](https://various.foodsafetykorea.go.kr/nutrient/general/down/historyList.do)
- **대상**: 가공식품 DB
- **시연에 쓴 버전**: `20260728_가공식품DB_306307건.xlsx` — 187.42 MiB · **306,307행 × 166열**
- 3주차 음식 DB(11MB·2만 건)와 같은 페이지, 15배 몸집입니다

성격 차이가 더러움의 원인입니다. 음식 DB는 **분석 기반**(연구 데이터)이고,
가공식품 DB는 **표시사항 수집 기반**(제품 라벨을 긁어모은 것)입니다.

### 원본은 레포 밖, 받는 방법은 레포 안

187MB를 커밋하는 선택지는 없습니다. `data/raw/`는 gitignore돼 있고, 재현은
스크립트가 보장합니다.

```bash
# 제공 중인 버전 목록 + 다운로드 안내
docker compose exec api uv run python scripts/download_file.py

# 받은 원본 검증 (행수·필수 컬럼·SHA-256)
docker compose exec api uv run python scripts/download_file.py --verify data/raw/<파일>.xlsx
```

내려받기 자체는 자동화하지 않습니다. K-FIND는 파일을 주기 전에 기관유형·소속·
사용목적을 묻는 짧은 설문을 받고, 그 답은 사람이 해야 합니다. 인증이 아니라
약속이라 스크립트가 우회할 자리가 아닙니다.

Open-API 경로(`scripts/download_api.py`)는 대조군입니다. 인증키가 필요하고,
1,000건씩 307번을 부르고, **09~19시에만 응답합니다.** 파일 경로를 기본으로
권장하는 이유가 이 제약들입니다.

### 커밋된 샘플 1,000건 — 왜 층화 샘플인가

`data/sample/raw_sample.csv`는 다운로드 없이도 원본을 관찰할 수 있게 커밋한
1,000건입니다. 166열 원본 그대로이고, 더러움을 치우지 않았습니다.

전수 조사해 보면 **인코딩 오염은 306,307건 중 54건(0.018%)**뿐입니다. 무작위로
1,000건을 뽑으면 기대값이 0.18건 — 대체로 한 건도 안 잡힙니다. "1,000건
훑어보니 깨끗하던데요"가 나오는 이유이고, 그 판단이 31만 건 배치를 깨뜨립니다.

그래서 두 층으로 뽑았습니다.

| 층 | 건수 | 무엇 |
| --- | --- | --- |
| 희귀 케이스 | 40 | BOM·전각 물음표·줄바꿈·NFD·앞뒤 공백이 실제로 든 행 |
| 계통 추출 | 960 | 파일 전체를 균등 간격(약 306행마다)으로 훑어 분포 보존 |

일부러 심었다는 사실 자체가 교훈입니다. **희귀 결함은 찾아 나서야 보입니다.**
결측률과 섭취참고량 분포 같은 "전체의 성질"은 계통 추출 층이 보존합니다.

재생성: `uv run python scripts/make_sample.py --input data/raw/<원본>.xlsx`

### 원본에서 실제로 관찰된 것

전수 조사 결과입니다 (`scripts/make_sample.py`와 같은 스캔).

**① 인코딩 오염 — 54건 (0.018%)**

| 유형 | 건수 | 실물 |
| --- | --- | --- |
| NFD 자모 분해 | 30 | 눈으로는 멀쩡한데 `==` 비교가 실패한다 |
| 제어문자(줄바꿈) | 10 | `퓔렌 프로틴 츄 망고향\n(퓔렌 프로틴 츄)` |
| 대체불가 문자 | 6 | `？스타곰탕 냉면 무김치` · `햇반컵반 스팸？마요덮밥` |
| BOM | 5 | `﻿우리밀 한입 스콘 초코칩` |
| 앞뒤 공백 | 3 | |

**② 결측 — 열의 성격에 따라 칼같이 갈린다**

결측이 무작위가 아닙니다. **라벨 의무 표시 항목만 채워져 있습니다.**

| 열 | 결측 | |
| --- | --- | --- |
| 에너지·단백질·지방·탄수화물·당류·나트륨·포화지방·트랜스지방·콜레스테롤 | 0.0\~0.03% | 라벨 의무 표시 9종 |
| 식품중량 | 5.3% | |
| 1회 섭취참고량 | 18.3% | |
| 식이섬유 97.1% · 칼슘 97.5% · 철 98.5% · 비타민 C 98.8% · 수분 99.8% | 90%+ | **125열** |
| 콜린·갈락토오스·불소 등 | 100% | **11열이 통째로 비어 있다** |

166열 중 **16열**만 남기는 컬럼 슬림의 근거가 이 표입니다 (식별 5 + 의무 표시 9
+ 섭취참고량·식품중량). 버리는 게 아니라 안 싣는 것이고, 원본은 `data/raw/`에
그대로 있습니다.

**③ 비정형 "1회 섭취참고량" — 고유값이 34개뿐이다**

자유 텍스트처럼 보이지만 실은 규정 표준값이라 사실상 통제 어휘입니다.
306,307건이 34개 문자열을 나눠 씁니다.

| 계층 | 고유값 | 행 | 실물 |
| --- | --- | --- | --- |
| 규칙: `숫자+g` | 16개 | 166,995 (54.5%) | `30g`(44,134건) · `70g` · `10g` · `100g` |
| 규칙: 다른 단위 | 6개 | 40,961 (13.4%) | `200ml`(27,258건) · `100ml` · `5ml` |
| 잔여 (규칙 실패) | **12개** | 42,378 (13.8%) | 아래 |
| 빈 값 | — | 55,973 (18.3%) | |

잔여 12개가 전부입니다. 눈으로 볼 수 있는 크기라, 보면 무엇이 필요한지 압니다.

| 유형 | 실물 |
| --- | --- |
| 단위 병기 (정규식 한 줄이면 됨) | `5g(ml)`(7,482) · `250ml(g)`(7,190) · `100g(ml)` · `200ml(g)` · `150ml(g)` · `80ml(g)` |
| 복합형 (구조를 뽑아야 함 → LLM) | `드레싱 15g, 덮밥소스 165g`(9,762) · `생·숙면 200g, 건면 100g, 당면 30g, 유탕면(봉지)120g, 유탕면(용기)80g`(8,151) · `액상 150ml, 호상 100ml(g)` · `레토르트 200g 기타 25g` · `분말 20g, 액상 200ml`(**1건**) |
| 판단 불가 (NULL이 정답) | `1식`(3,138) — 숫자가 없다 |

**고유값이 34개**라는 사실이 파싱의 비용 설계를 통째로 바꿉니다.

| | LLM 호출 | 비용 |
| --- | --- | --- |
| 행 단위로 순진하게 | 42,378번 | 약 $30 |
| 고유값으로 접어서 | **12번** | 약 $0.00008 |

3,500배입니다. 같은 문자열을 4만 번 다시 물을 이유가 없습니다.
`nunique()` 한 줄이 견적서를 다시 쓰게 만듭니다 — **LLM에 보내기 전에 세어보세요.**

## 저장소 구조

```
├── api/                   # FastAPI (오늘 만드는 것)
│   ├── app/main.py        #   v0.1: /health + 빈 상태 /foods
│   └── ...                #   v1.0: pipeline/ schemas/ api/routes/ tests/
├── ui/app.py              # Streamlit 3탭 (사전 구축 — 오늘 안 건드림)
├── data/
│   ├── sample/            #   커밋된 층화 샘플 1,000건
│   ├── raw/  clean/       #   원본·정제 산출물 (gitignore)
│   └── pg/  chroma/       #   서비스 볼륨 (2·3회전이 채움)
├── reports/               # 정제는 코드가 아니라 리포트로 검증한다
├── scripts/               # download_file · download_api · make_sample
├── docker-compose.yml     # api + ui (db는 2회전, chroma는 3회전이 추가)
└── PROMPT.md              # 회전별 지시 프롬프트 기록
```

### UI를 오늘 안 건드리는 이유

UI 코드는 v0.1부터 v1.0까지 한 줄도 안 바뀝니다. 바뀌는 것은 API가 돌려주는
데이터뿐이고, 빈 상태 화면이 검색 화면으로 바뀌는 순간이 파이프라인이 완성되는
순간입니다. 헤드리스 분리의 증명이고, 3주차와 같은 장면입니다.

세 탭은 API의 세 계층에 1:1로 대응합니다. **탭 순서가 곧 비용 사다리입니다.**

좁게 잡는 것도 설계입니다.
